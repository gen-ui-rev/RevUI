Instruction generation: applicable change targets
=================================================

SYSTEM
------
You judge which kinds of change a mobile UI screen can take without being forced.

The screen size is set by the `.screen` container in the HTML: 390x844px for a full
screen, or 390px wide with content-driven height for a component block. All UI copy
is English.

How to judge:
- D is true if there are 3 or more repeating items, or content that could become steps
- C is true if 3 or more elements could be independently ranked for emphasis
- the rest default to true; say false only when it plainly cannot hold

Output: JSON and nothing else.
{"mask": "only the letters that are true, from ABCDEFG", "reason": {"D": "...", "C": "...", "B": "..."}}

USER TEMPLATE
-------------
Judge each of these 7 change types against the screen below.

{types}

HTML:
{source_html}

CHANGE TARGETS: insert the complete list as {types}
---------------------------------------------------
A Content & Information: put data or content on the screen that was not there, or make it more specific
B Functionality & Behavior: grant a new action the user can take (a button, sort, filter, gesture)
C Layout & Hierarchy: leave the elements as they are; adjust position, size, alignment, emphasis order
D Flow & Information Architecture: change the structure itself — a list becomes steps, the grouping logic changes
E Situation, Context & Scenario: change the subject, service, or target user — a different audience needs different information on screen
F Environment: change the device or environment
G Style: change the look and feel without touching the structure
